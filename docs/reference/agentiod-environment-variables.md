# agentiod environment variables

Print the complete list, including binary defaults and descriptions, from the exact binary you plan to deploy:

```console
$ agentiod -print-env
```

From a source checkout, the equivalent command is:

```console
$ go run ./cmd/agentiod -print-env
```

The binary default applies when a variable is absent. The Helm chart sets many variables explicitly, so the effective value in a chart installation can differ from the binary default.

## Configure environment variables with Helm

Prefer a dedicated chart value when one exists. For example, `agentiod.logging.level` sets `AGENTIO_LOG_LEVEL`, and `agentiod.meshInternalTrafficPolicy` sets `AGENTIO_MESH_INTERNAL_TRAFFIC_POLICY`. Variables without a dedicated value can be passed through `agentiod.env`:

```yaml
agentiod:
  env:
    AGENTIO_KRT_DEBOUNCE: 250ms
```

After an environment-variable change, Helm rolls the `agentiod` Deployment. These variables are read when the process starts; changing a Pod's environment does not update a running process.

## Configuration groups

The `-print-env` output is the authoritative reference. Registered settings are grouped by prefix and purpose:

- control-plane identity and config: `AGENTIO_SERVICE_NAME`, `AGENTIO_TOKEN_AUDIENCE`, `AGENTIO_TRUSTED_NODE_ACCOUNTS`, and `AGENTIO_*CONFIGMAP_NAME`;
- advisory policy validation and status reporting: `AGENTIO_ENABLE_POLICY_STATUS` (default `true`);
- Kubernetes API client throttling: `AGENTIO_KUBERNETES_API_QPS` and `AGENTIO_KUBERNETES_API_BURST`;
- workload CA and trust distribution: `AGENTIO_CA_*`, `AGENTIO_TRUST_BUNDLE_*`, and `AGENTIO_WORKLOAD_CERT_*`;
- xDS and policy flow control: `AGENTIO_KRT_*`, `AGENTIO_PUSH_*`, `AGENTIO_CLIENT_QUEUE_SIZE`, and `AGENTIO_MAX_REQUESTS_PER_SECOND`;
- injection and gateway deployment: `AGENTIO_ENABLE_SIDECAR_INJECTOR`, `AGENTIO_INJECTOR_*`, `AGENTIO_NATIVE_SIDECARS`, `AGENTIO_ENABLE_CLIENT_TRUST_DISTRIBUTOR`, `AGENTIO_CLIENT_TRUST_PACKAGE_PATH`, `AGENTIO_ENABLE_GATEWAY_DEPLOYER`, and `AGENTIO_GATEWAY_LEASE_NAME`;
- networking: `AGENTIO_GATEWAY_*`, `AGENTIO_ENABLE_SNI_TRAFFIC_POLICY`, and `AGENTIO_MESH_INTERNAL_TRAFFIC_POLICY`;
- logging and debug access: `AGENTIO_LOG_*` and `AGENTIO_ENABLE_DEBUG_ON_HTTP`.

`AGENTIO_SANDBOX_MODE=false` (the default) disables Sandbox runtime discovery and Sandbox xDS output. Shared Workload policies remain enabled. Setting it to `true` enables Sandbox support alongside ordinary Workloads.

For Helm installations, use `sandbox.enabled` instead of environment overrides.
It configures `agentiod`'s mode and Kruise runtime discovery, managed EPE's Sandbox
rules, and the sidecar Sandbox Manager together. It defaults to `false` and is
only supported with `profile: sidecar`. EPE also reads `AGENTIO_SANDBOX_MODE` to
control its Sandbox rule watcher; configure it separately for external EPE.

`AGENTIO_SANDBOX_MODE=true` directly enables the built-in Kruise Sandbox source.
There is no runtime selection list. Remove `AGENTIO_SANDBOX_RUNTIMES` from existing
deployments; `agentiod` rejects the removed variable, including an empty value, with
a migration error. Deployments that previously enabled Sandbox mode but left the
runtime list empty should keep `AGENTIO_SANDBOX_MODE=false` if they do not want
Kruise discovery.

## Kubernetes API and xDS connection limits

| Setting | Default | Effect |
| --- | --- | --- |
| `AGENTIO_KUBERNETES_API_QPS` | `80` | Client-side Kubernetes API requests per second. |
| `AGENTIO_KUBERNETES_API_BURST` | `160` | Client-side Kubernetes API request burst. |
| `AGENTIO_MAX_REQUESTS_PER_SECOND` | `min(250 * CPU budget, 1000)` | Maximum new xDS streams accepted per second; zero selects the automatic default. |
| `AGENTIO_PUSH_CONCURRENCY` | `min(15 + 5 * GOMAXPROCS, 100)` | Concurrency limit for pushes and streams awaiting acknowledgements. |
| `AGENTIO_XDS_CPU_BUDGET` | empty | CPU budget for the automatic stream-admission rate; empty uses `min(NumCPU, GOMAXPROCS)`. |
| `AGENTIO_XDS_INITIAL_ADMISSION_TIMEOUT` | `10s` | Maximum wait for a new-stream initialization slot before authentication. |
| `AGENTIO_XDS_RATE_LIMIT_TIMEOUT` | `3s` | Maximum wait for new-stream rate admission. |
| `AGENTIO_XDS_SEND_TIMEOUT` | `15s` | Maximum duration of one response send. |
| `AGENTIO_XDS_ACK_TIMEOUT` | `20s` | Maximum time a response may remain unacknowledged. |
| `AGENTIO_XDS_MAX_POD_STREAMS` | `0` | Optional per-process dedicated Pod ADS stream cap; zero disables it. |

`AGENTIO_KUBERNETES_API_QPS` and `AGENTIO_KUBERNETES_API_BURST` configure client-side throttling only, not the API server's own limits. The stream-admission and push-concurrency settings bound new-stream acceptance and push concurrency. For recovery and capacity semantics, see [xDS connection limits](../design/xds-connection-limits.md).

New-stream admission timeouts do not apply to established streams waiting for response capacity; those streams apply backpressure. Send and ACK timeouts still close stalled streams. All four timeouts accept positive Go durations such as `500ms` or `15s`; invalid values fail startup. Set them through `agentiod.env`:

```yaml
agentiod:
  env:
    AGENTIO_KUBERNETES_API_QPS: "80"
    AGENTIO_KUBERNETES_API_BURST: "160"
    AGENTIO_XDS_INITIAL_ADMISSION_TIMEOUT: "10s"
    AGENTIO_XDS_RATE_LIMIT_TIMEOUT: "3s"
    AGENTIO_XDS_SEND_TIMEOUT: "15s"
    AGENTIO_XDS_ACK_TIMEOUT: "20s"
```

Longer send and ACK budgets retain slow clients and their response slots for longer; size them together with concurrency and memory limits.

## Kubernetes workload authentication

`AGENTIO_KUBERNETES_WORKLOAD_AUTH_MODE` selects the built-in authenticator for Kubernetes workloads at startup. The default, `local`, verifies Pod-bound JWTs locally and checks their Pod and ServiceAccount bindings against informer collections. To use Kubernetes TokenReview instead:

```yaml
agentiod:
  kubernetesWorkloadAuthMode: tokenreview
```

The OpenKruise sandbox-manager integration exposes the same setting at `agentio.agentiod.kubernetesWorkloadAuthMode`. Changing modes requires restarting agentiod; clients continue to send their existing projected ServiceAccount tokens.

In `local` mode, agentiod reads issuer discovery and `/openid/v1/jwks` using its authenticated Kubernetes client. The issuer is taken from that trusted discovery response, never from a client-supplied token. Public signing keys are cached for five minutes. A failed signature can trigger a key refresh, with refresh attempts limited to once every five seconds per replica. Refresh requests are serialized and use a five-second request timeout. After the key cache expires, failure to fetch keys rejects authentication. Discovery or initial key-loading failure prevents startup; authentication failures never fall back to TokenReview.

Local authentication checks the signature, issuer, audience, expiry, and applicable `nbf`/`iat` claims, then checks Pod and ServiceAccount names, UIDs, association, and deletion state against shared informer collections. Completed or failed Pods are rejected. Initial Pod and ServiceAccount synchronization is required before authentication succeeds and before the server becomes ready. This applies to xDS, certificate issuance, and authenticated debug requests. Unbound or legacy ServiceAccount tokens that work with TokenReview are not accepted in local mode.

Resource validity follows the existing informer's eventual-consistency behavior: deletion reaches authentication after the watch update is processed. A disconnected watch does not clear its cached resources, and initial synchronization is not a continuous freshness guarantee. Local mode therefore does not promise immediate revocation during watch interruptions. Authentication checks occur at connection or request admission; changing modes or deleting a Pod does not itself revoke an already issued certificate or immediately close an established stream.

Local verification removes per-authentication TokenReview calls. Initial discovery, signing-key refreshes, informer list/watch traffic, and kubelet token issuance and rotation still use the Kubernetes API server. Existing TokenReview cache hits can be faster than re-verifying a JWT locally.

## Shared Secret informer

`AGENTIO_SCOPED_SECRETS` defaults to `true`. The registry initializes one shared Secret informer in the root namespace, started with the server's Kubernetes client. Set the flag to `false` to watch all namespaces; cluster-wide Secret list/watch RBAC must be supplied separately. The scope is selected from this flag at startup, without RBAC probing. Fixed-name informers such as the MITM CA informer retain their configured namespace and name.

```yaml
agentiod:
  env:
    AGENTIO_SCOPED_SECRETS: "false"
```

## Client CA distribution and injection

`AGENTIO_ENABLE_CLIENT_TRUST_DISTRIBUTOR` defaults to `false`. The Helm chart derives it from `agentiod.injector.clientTrust.enabled` independently of the data-plane profile; use that single chart value to enable or disable the feature. In the ambient profile, enabling it also starts Pod admission and installs CA-only webhooks. When disabled, `agentiod` does not construct the distributor or allow CA injection, even with a Pod opt-in. The public CA package is built into the Agentiod image. Secret CA sources reuse existing system-namespace RBAC; the chart grants no additional source permissions. Disabling retains existing bundle ConfigMaps but stops updating them.

## Experimental UDP sessions

`AGENTIO_GATEWAY_ENABLE_UDP_PROXY` defaults to `false`. When enabled, every egress gateway accepts IPv4 CONNECT-UDP sessions on its HBONE listener. Hostnames and IPv6 targets are rejected.

UDP sessions are forwarded directly. Neither the CONNECT-UDP request nor the datagrams pass through external processing; EPE policies continue to apply only to the inner HTTP of ordinary TCP tunneling.

The flag only changes the gateway. Enable `ENABLE_UDP_PROXY=true` on each ztunnel and configure source Pod UDP TPROXY capture to port `15002`, preserving the original destination. Keep the capture mark distinct from ztunnel's `PACKET_MARK` (default `1337`) so the proxy's own sockets are not routed back into its listener. The default sidecar init only captures TCP; UDP capture requires a UDP-capable init or CNI. Keep DNS capture and exclusions separate.

```yaml
agentiod:
  env:
    AGENTIO_GATEWAY_ENABLE_UDP_PROXY: "true"
```

## On-demand TLS certificates

On-demand domain certificates use the `AGENTIO_MITM_*` settings. The chart maps `agentiod.mitm.secretName`, `agentiod.mitm.secretNamespace`, and `agentiod.mitm.signMode` to the corresponding CA variables. Lifetime, renewal, cache, and concurrency settings can be supplied through `agentiod.env`.

Domain certificates default to a 15-minute lifetime with a 1-minute renewal margin and a 15-minute resource TTL. SDS sets each resource's TTL to the time remaining until `min(SignedAt + ResourceTTL, NotAfter - RenewBefore)`, giving at most 14 minutes with the defaults. `AGENTIO_MITM_RESOURCE_TTL` can shorten that window. Reusing a cached certificate after reconnect does not extend that deadline. Expiry removes the secret from the gateway; the next request for the domain obtains a certificate on demand. Certificates whose remaining lifetime does not cover the renewal margin are refused, including certificates shortened by an expiring external CA.

`AGENTIO_MITM_CACHE_MAX_AGE` and `AGENTIO_MITM_CACHE_MAX_ENTRIES` control only the issuer's local cache. Cache eviction does not remove certificates already delivered to gateways. CA rotation or loss of gateway authorization still actively invalidates sent secrets.

Each actual issuance generates an independent ECDSA P-256 leaf key, including renewal for the same domain. Cache hits and concurrent requests sharing one issuance reuse the existing certificate and key. Clients must support ECDSA certificates; RSA-only clients cannot use these leaves.

`AGENTIO_MITM_SIGN_MODE` accepts:

- `SELF_SIGN`: Agentio owns and persists a self-signed CA in the configured Secret. This is the binary and chart default.
- `SECRET`: Agentio reads an externally managed CA Secret and does not rotate the root.

For an externally managed CA:

```yaml
agentiod:
  mitm:
    signMode: SECRET
    secretNamespace: agentio-system
    secretName: agentio-mitm-ca
```

The Secret must contain `ca.crt` and `ca.key`. Keep the Secret namespace and the configured egress-gateway identity scope consistent.

## Inspect the effective Pod environment

Inspect the rendered Deployment rather than relying only on chart defaults:

```console
$ kubectl get deployment agentiod \
    --namespace agentio-system \
    --output jsonpath='{range .spec.template.spec.containers[?(@.name=="discovery")].env[*]}{.name}{"="}{.value}{"\n"}{end}'
```

## Adjust the log level at runtime

When `AGENTIO_ENABLE_DEBUG_ON_HTTP` is enabled, the monitoring listener exposes an authenticated logging endpoint at `/debug/logging`. Each registered Agentio component has an independent output level. List the available components and their current levels with GET:

```console
$ curl http://127.0.0.1:15014/debug/logging | jq '.[] | select(.name == "default" or .name == "krt")'
{"name":"default","output_level":"info"}
{"name":"krt","output_level":"info"}
```

The exact list depends on the components linked into and initialized by the binary. Read one component or change only that component by adding its name to the URL. Valid levels are `debug`, `info`, `warn`, `error`, and `none`:

```console
$ curl http://127.0.0.1:15014/debug/logging/krt
{"name":"krt","output_level":"info"}

$ curl --request PUT \
    --header 'Content-Type: application/json' \
    --data '{"output_level":"debug"}' \
    http://127.0.0.1:15014/debug/logging/krt
```

`PUT /debug/logging` remains available and changes the `default` scope. The default scope covers standard-library, Kubernetes dependency, and other unscoped logs; it does not overwrite levels already assigned to registered components. At startup, `AGENTIO_LOG_LEVEL` initializes the default and every registered component to the same value.

Loopback requests do not require credentials. Requests from any other address must pass the configured Kubernetes workload authentication and the same root-namespace authorization as `/debug/configz`. A successful change returns HTTP 202 and affects existing loggers immediately. It is process-local and is not persisted: after an `agentiod` restart, `AGENTIO_LOG_LEVEL` supplies the level again.

## Configuration validation

`AGENTIO_VALIDATION_WEBHOOK_CONFIG_NAME` enables the `/validate` admission endpoint
on the shared HTTPS port 15017 and keeps the named ValidatingWebhookConfiguration's
CA bundle synchronized with the workload CA, including rotations. An empty value
disables validation admission. The Helm chart sets this name in both sidecar and
ambient profiles.

The webhook validates SecurityProfile, GlobalSecurityProfile, TrafficPolicy and
GlobalTrafficPolicy on CREATE and UPDATE, including dry runs. SecurityProfile
validation shares API static checks with policy status: selectors, priorities,
TLS constraints, reference and field unions, regular expressions, and CEL and Go
template syntax. It does not import EPE or check a consumer's expression variables,
helper functions, filter payloads, or ability to load the policy. TrafficPolicy validation checks selectors, priorities, actions,
protocols, port ranges and CIDRs without resolving live peers. CRD schema validation
continues to enforce structural constraints. Missing external references are
reported by policy status and do not prevent admission. Status updates and deletes
are excluded. The chart uses `failurePolicy: Fail`, so policy writes require an
available agentiod webhook.
