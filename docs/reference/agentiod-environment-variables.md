# Agentiod environment variables

Print the complete list, including binary defaults and descriptions, from the exact binary you plan to deploy:

```console
$ agentiod -print-env
```

From a source checkout, the equivalent command is:

```console
$ go run ./cmd/agentiod -print-env
```

The binary default applies when a variable is absent. The Helm chart sets many variables explicitly, so the effective value in a chart installation can differ from the binary default.

## Configure environment variables with Helm

Prefer a dedicated chart value when one exists. For example, `agentiod.logging.level` sets `AGENTIO_LOG_LEVEL`, and `agentiod.meshInternalTrafficPolicy` sets `AGENTIO_MESH_INTERNAL_TRAFFIC_POLICY`. Variables without a dedicated value can be passed through `agentiod.env`:

```yaml
agentiod:
  env:
    AGENTIO_KRT_DEBOUNCE: 250ms
```

After an environment-variable change, Helm rolls the `agentiod` Deployment. These variables are read when the process starts; changing a Pod's environment does not update a running process.

## Configuration groups

The `-print-env` output is the authoritative reference. Registered settings are grouped by prefix and purpose:

- control-plane identity and config: `AGENTIO_SERVICE_NAME`, `AGENTIO_TOKEN_AUDIENCE`, `AGENTIO_TRUSTED_NODE_ACCOUNTS`, and `AGENTIO_*CONFIGMAP_NAME`;
- advisory policy validation and status reporting: `ENABLE_POLICY_STATUS` (default `true`);
- Kubernetes API client throttling: `AGENTIO_KUBERNETES_API_QPS` and `AGENTIO_KUBERNETES_API_BURST`;
- workload CA and trust distribution: `AGENTIO_CA_*`, `AGENTIO_TRUST_BUNDLE_*`, and `AGENTIO_WORKLOAD_CERT_*`;
- xDS and KRT flow control: `AGENTIO_KRT_*`, `AGENTIO_PUSH_*`, `AGENTIO_CLIENT_QUEUE_SIZE`, and `AGENTIO_MAX_REQUESTS_PER_SECOND`;
- injection and gateway deployment: `AGENTIO_ENABLE_SIDECAR_INJECTOR`, `AGENTIO_INJECTOR_*`, `AGENTIO_NATIVE_SIDECARS`, `AGENTIO_ENABLE_CLIENT_TRUST_DISTRIBUTOR`, `AGENTIO_CLIENT_TRUST_PACKAGE_PATH`, `AGENTIO_ENABLE_GATEWAY_DEPLOYER`, and `AGENTIO_GATEWAY_LEASE_NAME`;
- networking: `AGENTIO_GATEWAY_*`, `AGENTIO_ENABLE_SNI_TRAFFIC_POLICY`, and `AGENTIO_MESH_INTERNAL_TRAFFIC_POLICY`;
- logging and debug access: `AGENTIO_LOG_*` and `AGENTIO_ENABLE_DEBUG_ON_HTTP`.

`AGENTIO_SANDBOX_MODE=false` (the default) disables Sandbox runtime discovery and Sandbox xDS output. Shared Workload policies remain enabled. Setting it to `true` enables Sandbox support alongside ordinary Workloads.

For Helm installations, use `sandbox.enabled` instead of environment overrides.
It configures Agentiod's mode and Kruise runtime discovery, managed EPE's Sandbox
rules, and the sidecar Sandbox Manager together. It defaults to `false` and is
only supported with `profile: sidecar`. EPE also reads `AGENTIO_SANDBOX_MODE` to
control its Sandbox rule watcher; configure it separately for external EPE.

`AGENTIO_SANDBOX_MODE=true` directly enables the built-in Kruise Sandbox source.
There is no runtime selection list. Remove `AGENTIO_SANDBOX_RUNTIMES` from existing
deployments; Agentiod rejects the removed variable, including an empty value, with
a migration error. Deployments that previously enabled Sandbox mode but left the
runtime list empty should keep `AGENTIO_SANDBOX_MODE=false` if they do not want
Kruise discovery.

## Environment variable reference

This table is generated from the binary's registered `AGENTIO_*` variables. Defaults are the values declared by the binary, before Helm overrides or runtime resolution. `AGENTIO_PUSH_CONCURRENCY` has a CPU-dependent default described in its row. Types describe the registered input, so a setting parsed as a duration after registration can appear as `String`.

To export the table from a binary:

```console
$ agentiod -print-env -print-env-format=markdown
```

`-print-env` in its default text format also includes visible variables registered by dependencies. Neither format reads current values for the table, and variables read without `env.Register`, such as `KUBECONFIG`, are not listed.

KRT debounce applies only to TrafficPolicy and SecurityProfile events, including policies derived from Sandbox inline rules. Pod identity, Sandbox identity and binding, Service, EndpointSlice, Gateway, ConfigMap and Secret events do not have a KRT debounce window. Global xDS push debounce is disabled by default; explicitly setting `AGENTIO_PUSH_DEBOUNCE` to a positive duration enables a publication delay for all resource types and requires a matching `AGENTIO_PUSH_DEBOUNCE_MAX`.

## Kubernetes API and xDS connection limits

Agentiod configures its Kubernetes clients with **80 QPS** and a **burst of 160**. This avoids falling back to client-go's lower defaults during informer startup, relists, and TokenReview calls. Both settings must be positive; QPS must also be finite and representable as a positive float32.

Override them through the existing Helm environment map:

```yaml
agentiod:
  env:
    AGENTIO_KUBERNETES_API_QPS: "80"
    AGENTIO_KUBERNETES_API_BURST: "160"
```

These settings configure client-side throttling, not the Kubernetes API server's limits or a single aggregate budget shared by all clientsets and replicas. Higher settings allow more API traffic; choose values appropriate for the API server's capacity.

`AGENTIO_MAX_REQUESTS_PER_SECOND` separately limits **new xDS streams** before authentication. Its default is `min(250 * C, 1000)`, with a burst of 1 and up to 1 second of waiting before rejection. An explicit positive value overrides that default, including the automatic cap; zero selects the automatic default. This limit does not throttle ACKs on established streams or server-initiated configuration pushes, and increasing it does not fix slow-client push accumulation. The separate `AGENTIO_PUSH_CONCURRENCY` default remains `min(15 + 5 * GOMAXPROCS, 100)`.

`C` is the CPU budget supplied through `AGENTIO_XDS_CPU_BUDGET`, bounded by `min(NumCPU, GOMAXPROCS)`. The budget accepts Kubernetes CPU quantities such as `500m` or `2`; the chart supplies the agentiod CPU limit when present, otherwise its CPU request. An explicit entry in `agentiod.env` overrides the chart-derived budget. The default chart request of `500m` therefore selects 125 new streams/s; budgets of 1, 2, and 4 CPUs select 250, 500, and 1,000/s when the runtime allows those CPU counts. A CPU request is a planning budget, not a hard CPU limit; a CPU limit likewise does not guarantee that much CPU under host contention.

With an empty budget, including a binary run outside the chart, `C` falls back to `min(NumCPU, GOMAXPROCS)`. This fallback cannot distinguish fractional CPU quotas rounded by the Go runtime; set an explicit budget for such deployments. Startup logs record the supplied budget, effective CPU count, fallback use, and final admission rate. The automatic cap is a tested default, not a universal capacity limit or a recovery-time guarantee. Cold TokenReview throughput, configuration size, slow receivers, and the number of surviving control-plane replicas also constrain recovery.

Initial responses, requests on established streams, and background responses use three independent pools, each sized by `AGENTIO_PUSH_CONCURRENCY`. A stream becomes established after a valid ACK or NACK for a response actually sent on that stream; old valid nonces count, unknown nonces do not. Asynchronous SDS responses use the same distinction, so slow initial clients cannot exhaust capacity reserved for established demand queries. A stream holds one slot until its outstanding responses are acknowledged or the stream closes; all response types on that stream share the slot. Pure ACK/NACK processing needs no additional slot. Client-requested responses wait at most 1 second for capacity, after which the stream ends with `ResourceExhausted`; a shorter caller deadline wins. Background pushes retain the existing bounded scheduler queue and wait for response capacity until the stream is canceled, avoiding reconnects merely because another client is applying a batch of updates.

A blocked send or a response left unacknowledged for 5 seconds ends the stream with `DeadlineExceeded` and releases capacity. Acknowledging a previously sent nonce advances that type's progress, while unknown nonces and progress on another type cannot hide a stalled response. This also bounds slow receivers when gRPC accepts a send into its internal queue before the peer reads it. Rejected streams must reconnect. The separation protects established demand queries from slow initial clients; established clients that later become slow still share their request pool. For example, an Envoy that ACKs a small CDS response before subscribing to a large RDS response already uses the established pool for subsequent leases. These bounds do not guarantee uninterrupted queries during every overload.

A cold TokenReview has a 5-second budget covering both client-side API throttling and the API call. A shorter caller deadline wins; a successful cached identity returns without that wait. API failures return `Unavailable`, while rejected credentials still return `Unauthenticated`. The cache lifetime and capacity are unchanged. The authentication, scope-readiness, capacity-wait, send, and acknowledgement budgets are separate stages, not a single end-to-end recovery deadline.

After authentication, a stream can wait up to 5 seconds for its bound Pod and derived Workload to appear in local caches. This performs local key lookups, not additional API requests. A timeout returns `DeadlineExceeded`; identity mismatches still return `PermissionDenied` immediately. No configuration is sent before scope resolution completes.

For large clusters, provision control-plane CPU, memory, and replicas, and configure the existing stream-admission and Kubernetes API limits to match the measured capacity of the deployment.

## Shared Secret informer

`AGENTIO_SCOPED_SECRETS` defaults to `true`. The registry initializes one shared Secret informer in the root namespace, started with the server’s Kubernetes client. Set the flag to `false` to watch all namespaces; cluster-wide Secret list/watch RBAC must be supplied separately. The scope is selected from this flag at startup, without RBAC probing. Fixed-name informers such as the MITM CA informer retain their configured namespace and name.

```yaml
agentiod:
  env:
    AGENTIO_SCOPED_SECRETS: "false"
```

## Client CA distribution and injection

`AGENTIO_ENABLE_CLIENT_TRUST_DISTRIBUTOR` defaults to `false`. The Helm chart derives it from `agentiod.injector.clientTrust.enabled` in the sidecar profile; use that single chart value to enable or disable the feature. When disabled, agentiod does not construct the distributor or allow CA injection, even with a Pod opt-in. The chart also omits the public CA package init container. Secret CA sources reuse existing system-namespace RBAC; the chart grants no additional source permissions. Disabling retains existing bundle ConfigMaps but stops updating them.

## Experimental UDP sessions

`AGENTIO_GATEWAY_ENABLE_UDP_PROXY` defaults to `false`. When enabled, every egress gateway accepts IPv4 CONNECT-UDP sessions on its HBONE listener. Hostnames and IPv6 targets are rejected.

UDP sessions are forwarded directly. Neither the CONNECT-UDP request nor the datagrams pass through `extProc`; EPE policies continue to apply only to the inner HTTP of ordinary TCP HBONE.

The flag only changes the gateway. Enable `ENABLE_UDP_PROXY=true` on each ztunnel and configure source Pod UDP TPROXY capture to port `15002`, preserving the original destination. Keep the capture mark distinct from ztunnel's `PACKET_MARK` (default `1337`) so the proxy's own sockets are not routed back into its listener. The default sidecar init only captures TCP; UDP capture requires a UDP-capable init or CNI. Keep DNS capture and exclusions separate.

```yaml
agentiod:
  env:
    AGENTIO_GATEWAY_ENABLE_UDP_PROXY: "true"
```

## On-demand TLS certificates

On-demand domain certificates use the `AGENTIO_MITM_*` settings. The chart maps `agentiod.mitm.secretName`, `agentiod.mitm.secretNamespace`, and `agentiod.mitm.signMode` to the corresponding CA variables. Lifetime, renewal, cache, and concurrency settings can be supplied through `agentiod.env`.

Domain certificates default to a 15-minute lifetime with a 1-minute renewal margin and a 15-minute resource TTL. SDS sets each resource's TTL to the time remaining until `min(SignedAt + ResourceTTL, NotAfter - RenewBefore)`, giving at most 14 minutes with the defaults. `AGENTIO_MITM_RESOURCE_TTL` can shorten that window. Reusing a cached certificate after reconnect does not extend that deadline. Expiry removes the secret from the gateway; the next request for the domain obtains a certificate on demand. Certificates whose remaining lifetime does not cover the renewal margin are refused, including certificates shortened by an expiring external CA.

`AGENTIO_MITM_CACHE_MAX_AGE` and `AGENTIO_MITM_CACHE_MAX_ENTRIES` control only the issuer's local cache. Cache eviction does not remove certificates already delivered to gateways. CA rotation or loss of gateway authorization still actively invalidates sent secrets.

Each actual issuance generates an independent ECDSA P-256 leaf key, including renewal for the same domain. Cache hits and concurrent requests sharing one issuance reuse the existing certificate and key. Clients must support ECDSA certificates; RSA-only clients cannot use these leaves.

`AGENTIO_MITM_SIGN_MODE` accepts:

- `SELF_SIGN`: Agentio owns and persists a self-signed CA in the configured Secret. This is the binary and chart default.
- `SECRET`: Agentio reads an externally managed CA Secret and does not rotate the root.

For an externally managed CA:

```yaml
agentiod:
  mitm:
    signMode: SECRET
    secretNamespace: agentio-system
    secretName: agentio-mitm-ca
```

The Secret must contain `ca.crt` and `ca.key`. Keep the Secret namespace and the configured egress-gateway identity scope consistent.

## Inspect the effective Pod environment

Inspect the rendered Deployment rather than relying only on chart defaults:

```console
$ kubectl get deployment agentiod \
    --namespace agentio-system \
    --output jsonpath='{range .spec.template.spec.containers[?(@.name=="discovery")].env[*]}{.name}{"="}{.value}{"\n"}{end}'
```

Values populated through `valueFrom`, such as `POD_NAME`, are shown without their runtime value by this command.

## Adjust the log level at runtime

When `AGENTIO_ENABLE_DEBUG_ON_HTTP` is enabled, the monitoring listener exposes an authenticated logging endpoint at `/debug/logging`. Each registered Agentio component has an independent output level. List the available components and their current levels with GET:

```console
$ curl http://127.0.0.1:15014/debug/logging | jq '.[] | select(.name == "default" or .name == "krt")'
{"name":"default","output_level":"info"}
{"name":"krt","output_level":"info"}
```

The exact list depends on the components linked into and initialized by the binary. Read one component or change only that component by adding its name to the URL. Valid levels are `debug`, `info`, `warn`, `error`, and `none`:

```console
$ curl http://127.0.0.1:15014/debug/logging/krt
{"name":"krt","output_level":"info"}

$ curl --request PUT \
    --header 'Content-Type: application/json' \
    --data '{"output_level":"debug"}' \
    http://127.0.0.1:15014/debug/logging/krt
```

`PUT /debug/logging` remains available and changes the `default` scope. The default scope covers standard-library, Kubernetes dependency, and other unscoped logs; it does not overwrite levels already assigned to registered components. At startup, `AGENTIO_LOG_LEVEL` initializes the default and every registered component to the same value.

Loopback requests do not require credentials. Requests from any other address must pass the same TokenReview and root-namespace authorization as `/debug/configz`. A successful change returns HTTP 202 and affects existing loggers immediately. It is process-local and is not persisted: after an `agentiod` restart, `AGENTIO_LOG_LEVEL` supplies the level again.
